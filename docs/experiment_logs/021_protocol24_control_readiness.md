## Bad case与工程问题

1. 只读题后台真值正确但没调用状态工具：2.3可通过，新2.4明确拒绝。
2. 日志请求放前导致先查空日志：新题公开要求所有操作尝试后再查；过早日志即使包含看似正确内容也被时序检查拒绝。
3. 动作成功自带完整终态或verify返回状态：接受，不重新限制唯一inspect。
4. Base误指定adapter、未知契约、query改变、指纹错配、重复case、部分覆盖：参数/校验测试覆盖；测试中出现的argparse拒绝是预期负例，不是新的SuperPOD失败。
