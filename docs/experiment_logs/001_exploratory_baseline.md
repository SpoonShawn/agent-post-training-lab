# 001 — 早期 7 条探索 baseline

## 状态与证据

已完成的真实模型推理，2026-09-10 回顾补录；实际运行日期未在此记录中确认。产物提交 `2ff581a`，来源 [原始输出](../../results/baseline/qwen3_4b_baseline.jsonl)。

## 实验目标

验证 Qwen3 的基础 Tool Calling，以及知识查询、状态读取、复现、规避、恢复和无需工具回答是否可运行。探索性小样本，不用于泛化结论。

## 配置

历史对话称 Qwen3-4B；本轮未从 v1 产物核实完整权重哈希、依赖版本、GPU 型号、采样参数或运行时长，不借用 v2 配置补填。实际轨迹最长 12 steps，不据此推定所有用例共用同一预算。

## 数据集

原始输出含 7 个 case：knowledge、build、state、repro、workaround、recovery、no_tool 各 1 条。样本过少，且不包含稳定的状态/答案级任务成功评估。

## 指标

历史文件记录工具名序列、步数、非法/失败/未知调用、ordered match 与 tool-set match。recovery 缺少后两项，不能将缺失当成 false，也不能宣称已有完整任务成功率。

## 结果

- 有轨迹匹配记录的 6 条中，3 条 ordered match 和 set match 为 true，3 条 false：3/6=50%。另 1 条未记录。
- 7 条总计 33 Agent steps，均值约 4.71。
- 失败工具执行共 14 次：repro 4、workaround 9、recovery 1。
- 已记录的非法和未知工具调用均为 0。

## Bad case

- `knowledge_001`：先 get_build_info 再 search_knowledge，被单一工具参考路径判不匹配；只能说明路径多一步，不能仅据此断言任务失败。
- `repro_001`：9 steps、4 次执行失败，工具顺序混乱。
- `workaround_001`：12 steps、9 次失败，多次重复检索后重复动作。
- `recovery_001`：出现一次失败后继续调用，但旧指标不足以确认恢复完成。

## 遇到的问题

轨迹匹配不等于任务完成；恢复指标缺失；长链路反复失败；本次补录的口头计数一度出错（见勘误）。

## 原因分析

确定：旧指标只覆盖调用层，无法验证完整目标。轨迹显示执行失败和重复行动，但仅凭 7 条不能判断是模型、工具说明还是环境设计各贡献多少。

## 解决方案与设计变更

先升级 benchmark 和 evaluator，再训练。引入目标状态、工具证据、答案条件和可控故障注入，而不是把 exact match 当唯一成功标准。

## 验证

本次直接读取 7 条原始 metrics 核对计数，未重新推理；缺失字段按缺失保留。

## 追加记录／勘误

2026-09-10：本次补录时助手曾口头说“4/6”，属计数错误，已纠正。原始 true 仅 build_001、state_001、no_tool_001；knowledge_001、repro_001、workaround_001 为 false；recovery_001 缺失。早期对话的“3/6=50%”是正确的。教训：统计应由记录计算，不凭浏览输出后的记忆计数。
