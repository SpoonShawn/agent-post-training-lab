# 010 — 训练前题面与评分条件清查

## 状态与证据

清查阶段完成；协议尚不能宣称冻结。记录日期2026-09-14，现场记录，基于55a5507。性质：作者AI模板审查及CPU模拟反例，不是新模型推理、独立人工审查或训练。

输入：[v2.2基准](../../results/audit/v22/benchmark_v22.jsonl)、生成脚本、系统提示、工具与评分代码。输出：[360条清单](../../results/audit/contracts_v22/inventory.jsonl)、[4组模拟轨迹](../../results/audit/contracts_v22/probes.jsonl)、[汇总](../../results/audit/contracts_v22/summary.json)。

## 实验目标

训练前检查“用户看得到的任务要求”与“隐藏成功条件”的一致性，明确测量缺口和业务简化程度。没有预设分数改善目标；不把题量等同独立业务覆盖。

## 配置

协议2.2不变，原始模型输出和答案标签不变；CPU使用现有模拟环境与工具执行参考路径及变体。无GPU、权重加载、训练参数或模型生成时间。完整输入SHA-256：21ff94a48f40ce6ed08b31c24ffad8384f70c8b025ee0fb15fdad637d9e3e5dd。

## 数据集与审查范围

读取12个任务族的生成分支、知识库、系统提示和现行执行评分，再由显式模板检查导出360行。180个scenario_id；按environment+required_calls做严格相等去重为166种签名，该数不是独立语义场景数。知识库共8条：2个历史事件、3条构建记录、3条UI指南。文件held_out字段是历史元数据，研究用途仍为开发/审计集。

本轮只检查已定义的5类风险，不宣称自动理解全部自然语言要求或穷尽全部漏洞；首轮答案一致性抽查尚未完成。

## Bad case：4组程序执行反例

每组先运行原参考调用（执行通过），再运行变体；两者最终环境状态相同。均没有模型最终答案，不能称任务通过或新模型表现。

1. negative_control_ios_001：删去题面未要求的query_logs，仍正常加载且verify成功，但执行评分失败。
2. reproduce_black_screen_001：把search_knowledge移到实际复现之后，违反“先核对再复现”，执行评分仍通过。
3. navigate_graphics_005：已经在graphics，题目要求不做多余跳转；先返回首页再进入graphics，执行评分仍通过。
4. build_info_001：用inspect_ui_state代替get_build_info，返回完整版本/平台且不改变环境，执行评分失败。

这些是构造的反例，不把它们当作Qwen3实际发生的四个bad case。每组原始调用/返回/终态见probes.jsonl。

## 遇到的问题与原因分析

已证实：条件集合只能表达“做过什么”，不能保证“什么时候做”；终态只能表达“最后是什么”，不能保证“过程中没改过”。一些业务证据要求停留在作者隐含假设里，没有公开给模型。另一方向又把提供证据的工具身份当成证据内容本身。

作者曾用正向oracle全通过判断基准可用；本轮变体证明这不足以说明判别器正确。规则校准反复出现的原因之一是缺少预先完成的任务契约，而不是模型格式能力弱。

业务覆盖较小不是本身的实现bug，但限制结论：只能称合成BugOps微型基准，不能写成360个独立真实缺陷、真实移动端回归能力或生产可用性证明。

## 解决方案与设计变更

新增可重复的清查脚本和测试，仅报告风险与模拟反例，不修改2.2得分。保留所有旧材料。训练数据仍为空，未从旧评测问题/答案/轨迹生成任何训练数据。

下一版应先公开统一任务契约再冻结：凡日志是硬条件，题面明确要求；凡先后顺序/禁止动作是要求，写入结构化条件并测试；结果证据用字段和来源能力约束，避免无意义工具身份绑定。涉及输入或系统提示改变的题，必须新推理，不能复用旧答案冒充同一实验。

不采用“把所有隐藏要求塞进训练集，让模型学会猜评测器”的方案。也不为赶进度将当前审查集直接随机切成训练/测试集。
