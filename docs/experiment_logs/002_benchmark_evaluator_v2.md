# 002 — Benchmark / Evaluator v2 构建

## 状态与证据

工程阶段已完成，2026-09-10 回顾补录。实现提交 `287ffee`；见 [指标定义](../evaluator_v2.md)、[生成器](../../scripts/generate_benchmark_v2.py)、[评估器](../../evaluation/evaluator.py)。本阶段不是 GPU 模型实测。

## 实验目标

从 7 条探索样例扩展到可重复的多场景 benchmark，支持状态可验证、故障可控和后续同条件模型对比。

## 配置

Evaluator 2.0，合成 BugOps 状态机、知识库和工具；支持逐 case 隐藏初态和确定性故障。使用参考调用轨迹构造 oracle，不加载模型权重。具体本地硬件和该阶段运行时长未记录。

## 数据集

[冻结的 v2 输入](../../data/eval/bugops_eval_v2.jsonl)：360 条，12 任务族 × 15 场景 ID × 2 表述；180 个场景 ID 不等于 180 个统计独立样本。类别分布：knowledge 60、single_tool 60、navigation 30、long_horizon 120、recovery 60、no_tool 30。交错排列便于小规模 smoke test 覆盖不同任务。

SHA-256：`7851b5ca356953d56621be62943dc00ee3b63aa07e02e5cb825f4986f08b2c4a`。最初按 held-out 设计；经后续规则开发，现须标为开发／审计集，不再声称独立确认性测试。

## 指标

增加工具 precision/recall、参数匹配、调用合法性、原始/调整后执行成功、重复率、终态、工具返回证据、答案条件、恢复与长链路成功、分类/难度/任务族汇总。工具参考轨迹匹配与 task_success 分开。

## 结果

360 条参考轨迹通过 oracle 检查；runner 支持结果逐条保存、内容指纹和严格续跑。该结果仅证明参考路径可执行，不是模型 100% 成功，也不证明所有合理替代路径会通过。

## Bad case

后来实际 baseline 暴露：`navigate_graphics_001` 的等价动作证据被拒；`negative_control_ios_002` 的否定句误触发禁词；`knowledge_black_screen_011` 的问题未给事件编号。这些是回顾发现，不假称在构建时已经识别。

## 遇到的问题

oracle 只测参考正例，缺少等价路径和语言反例；自由文本 query 精确匹配过严；输入可回答性审查不足；部分隐藏证据要求与题面显式要求可能不一致。

## 原因分析

把“参考路径可行”误当作“评估协议充分验证”，测试范围存在盲点。状态驱动设计虽比 exact match 更合理，但仍保留过强的工具身份和脆弱答案规则。

## 解决方案与设计变更

保留 v2 快照，在 v2.1 独立修订并记录影响。增加等价路径、缺必要证据、错误结论不自动通过、输入修订需新推理等测试。不能通过修改旧数据抹去设计缺陷。

## 验证
