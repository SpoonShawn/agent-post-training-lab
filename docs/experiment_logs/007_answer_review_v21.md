## 遇到的问题与原因分析

1. **执行通过不保证回答正确**：检索取得目标记录后，模型仍可能跨平台/版本拼接、扩写因果或修复结论。任务需验证报告而非只验证工具结果。
2. **最终成功不代表全过程无错误**：return_home_then_dungeon_029 的绝对化全过程断言与四次工具失败直接冲突。
3. **截断不等于所有内容无效，也不能忽视**：no_tool_005/006/011/012 的结尾截断，但所问核心解释此前已给出，首轮按既定核心事实规则 pass 并标记质量缺陷；未新增“必须独立结论段”之类评分要求。ui_state_019 完全没有答案则 fail。
4. **通过不等于完美**：泛泛的“符合预期”、非核心术语错误、语气绝对和过长回答均在理由中保留。作者将有明确证据冲突或具体平台/版本/因果扩张视为更实质的问题。此边界带有主观性，需校准，不能声称无偏。
5. **恢复检查的残余规范问题**：recovery_navigation_021、recovery_action_010/011/019/024 等未必在故障后独立 inspect，但 v2.1 接受反馈/动作证据。答案未声称不存在的检查时，不以本轮新加的工具身份要求追罚；题面“检查状态后重试”与协议如何对齐留待规范审查。
6. **统计口径容易混淆**：206 是执行通过队列；352 是旧轨迹可重评分分母；8 条补跑是另一运行。不能直接说 191/206 为全 benchmark 成绩，也不将两批拼接后发布统一运行分数。
