# 030 — 同历史同答案的呈现多样性对照准备

## 状态与证据

2026-09-16本地准备完成；非回顾补录。前阶段结果来源ef2b42c，本阶段新增training/evidence_ablation.py、准备/GPU/启动脚本、data/evidence_ablation_v1冻结包及测试。无本轮真实模型推理或训练，真实GPU、耗时、token数待上机记录。用户要求预估完成时间并推进到需其操作，本阶段到达GPU协助边界。

## 实验目标

阶段029证明旧报告LoRA在原格式满分，但换写、历史增长、当前权限更新时不稳。此次将范围收敛为一个可解释对照：相同新历史和答案，固定布局训练与混合布局训练是否在未见事件结构组合上有不同表现。假设可能成立也可能失败；不预设涨分。

## 配置

Base及依赖版本沿用control_v1冻结记录。fixed/mixed两个新LoRA从Base独立初始化，同seed20260916，r16/alpha32/dropout0.05/all-linear，lr1e-4，batch1、accumulation8、1epoch/24步，最后epoch而非确认集选优。两步smoke使用mixed且独立目录，不继续为正式模型。训练预算与监督答案相同，不承诺输入token或FLOPs相等；GPU预检逐组记录并验证监督token序列一致。

生成greedy、512输出、4096上下文。Base先288题，再两组训练，最后两adapter各288题。确认结果不参与训练、选checkpoint或参数决策。使用H800属于预期资源，实际型号以用户运行记录为准。申请2小时，估计1–2小时运行，不含排队，不作性能保证。

## 数据集与泄漏边界

新生成288个上下文：192训练/48验证/48确认，共48事件结构组，32/8/8划分。四类历史clean/transient/arguments/policy，各类3种重复次数×4种最后验证/顺序结构，形成12组；按固定哈希在每类分8/2/2组。每组2平台×3画质共6变体，整组不得跨split。

历史从图形页观测和日志开始，多轮“失败验证—不同工具事件—日志—成功验证”，可写历史随后返回首页，再按组规定顺序追加最后检查、观测/日志。当前只读按变体交替，与历史只读分开。所有正式题的返回来自模拟器实际执行，不伪造输出。新旧共用工具原语和报告字段，因此不是全新业务语义独立性的证明。

fixed使用单一JSON布局，mixed三布局每种64训练题；同一位置对应相同历史与目标，未增加例数。按组打散布局分配，不固定绑定平台/画质。评估每上下文三种布局，各split144题，每布局48，跨模型完全相同。确认集不导出训练轨迹。

先生成后将旧报告训练/验证/确认及压力题仅用于拒绝检测；规范化工具调用序列忽略value与verify值，保留工具/参数结构/检查字段，拒绝旧事件骨架重复，并拒绝新split间骨架重复。此检查比仅字符串查重强，但不是完整语义去重，不能声称彻底消除泄漏。旧压力题只用于确定问题类型，不作为新题或其改写输入。所有旧来源SHA、新文件SHA与运行代码SHA在manifest固定。

## 指标及比较限制

评分沿用training/evidence_pilot.py，不修改历史结果。主比较确认集每布局48题的exact_report及fixed→mixed成对转移，同时按8组观察；辅指标valid_json、decision_correct、字段错误、耗时和token预算。不能把三布局的144题或三个模型864次当独立样本。缺行或指纹不一致不发布完整结论。

与阶段027/029直接比较存在题面、历史与数据划分混杂。本轮结论限于fixed vs mixed的布局训练差异；不能据新成绩声称“只增加历史覆盖就提升”或“只增加样本数就解决过拟合”。新历史丰富程度并非本轮消融变量，因为两臂相同。

## 结果与Bad case

当前只有构造和本地测试结果，无模型成绩。保留阶段029的121条真实失败，不纳入本轮正向训练。新增最小单元反例分别检查：仅追加成功验证改变最后matches；重复相同日志不累计log_count；只翻转当前权限仅改变decision。这些是程序性质测试，不是模型通过率。

## 遇到的问题与原因分析

1. 旧满分无法外推，且仅比较旧模型和新模型会同时改变数据、题面、长度、格式，无法解释收益来源。解决：两新臂使用相同历史与答案，只控制呈现布局；Base重测作为新任务参考。
2. 只按题目字符串去重会漏掉换平台/画质的同历史。解决：按底层组合整组隔离，再检查去除部分取值后的调用骨架；明确共享原语仍造成关联。
3. 等样本不等算力。解决：两组监督答案与优化步数一致，但记录实际输入token/时间，拒绝称严格等计算实验。
4. 本地无4B权重和GPU依赖，不能凭单元测试承诺上机运行。解决：把真实分词、内容哈希、bf16、版本校验放在模型运行前；超过长度即停止，保留失败记录。
5. 先前不断增加实验会拖延交付。解决：预先设收尾条件，本轮正负结果都归档，不按成绩无限追加训练；DPO/GRPO不纳入本次完成时间。

## 解决方案与兼容性

新文件和独立checkpoint/results目录，不修改旧冻结生成器、评分器、adapter或成绩。训练只监督最终报告，历史失败调用在用户证据中，不成为正向工具行动目标。推理不执行模型输出的调用。

预检记录写保护；重复执行验证来源后跳过完整结果；不完整训练拒绝覆写，推理拒绝重复/漂移/损坏记录。Shell任一阶段失败立即退出，不继续消耗GPU。所有GPU入口进入仓库且先检查资源，不在登录节点推理。
