# 005 — v2.1 正式接线与复核支持

## 状态与证据

工程阶段完成；记录日期 2026-09-10，回顾补录。提交 `4a2bf12` 已推送。详见 [问题复盘](../experiment_lessons_v21.md)、[操作指南](../protocol_v21.md)、[统一评分入口](../../evaluation/scoring.py)。不是训练或新 GPU 推理阶段。

## 实验目标

让修订在正式运行与汇总中真正生效，防止旧逻辑重算新输入、待审分母偏差、旧复核误套新答案和历史输出覆盖。

## 配置

runner/summarizer 按 case.protocol_version 分流，缺省保持 v2 兼容；2.1 始终重新计算执行，答案判定通过显式 --reviews 加载。新评分代码进入运行指纹。CPU 本地测试，无 GPU 推理；本地 Python 精确版本和硬件未在该阶段产物中记录。

## 数据集

原始 360 条模型轨迹未改；重建 v2.1 审计产物、206 条证据队列和 8 条补跑输入。测试含合成 oracle 和真实 baseline；测试复核判定仅写临时目录，不作为真实审阅记录。

## 指标

正确协议分流、严格来源校验、待审数量和逻辑上下界、历史兼容、原输出哈希不变、自动化测试通过情况。模型 task_success 仍未得到复核后的新总分。

## 结果

- 95 项测试通过：`python3 -m unittest discover -s tests -q`。
- v2.1 接入 runner/summarizer；未知/混合协议及 query 不一致拒绝。
- 复核绑定源文件与逐条 case/result 哈希，保留审阅者类型、理由和时间。
- 待审不从分母悄悄删除；执行失败即使答案被判 pass 也不能成为任务成功。
- 已有推理输出禁止无意覆盖；新运行需新路径或合法 resume。
- 审计仍是 206/352 执行通过、206 条待审、8 条待补跑；没有新增已确认的模型成绩。

## Bad case

工程反例：一条失败、一条待审，旧通用平均会给出 0/1 而非“整体未决”；同 ID 新答案沿用旧 pass；v21 文件名却调用 v2 scorer；新代码直接覆盖老输出。均通过对应测试防护，而非模型 bad case。

## 遇到的问题

独立审计脚本与正式入口脱节；null 聚合有选择性分母风险；复核 provenance 缺失；此前操作指导未先进入目录/申请 GPU；读者可能误把 oracle 或单元测试当模型成功。

## 原因分析

协议变化会影响调用端、元数据、聚合和运行管理，不只影响一个判定函数。CPU 审计与 GPU 推理被混写指令会造成操作风险。有限测试不能证明答案复核质量。

## 解决方案与设计变更

统一版本入口、复核队列导入、完整未决计数、新结果防覆盖、明确 SuperPOD 登录节点与计算节点步骤。旧 352 条与新 8 条来源不同，禁止简单拼接当作同一运行；目前分别报告，统一成绩优先完整重跑并复核。

## 验证

95 项通过，包含真实 baseline 重审/临时复核导入/原输出 SHA 未变。原始数据仍为阶段 003 的来源 SHA；Git 工作区在该提交完成时干净。未申请实际 SuperPOD GPU、未完成 206 条语义审阅，也未验证生产 GUI 环境。
