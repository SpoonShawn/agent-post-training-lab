# 实验动机

## 背景

本项目来源于真实业务 AI Agent 落地过程中的工程观察。

在实习项目中，Agent 系统主要通过调用外部大模型 API，并结合 RAG、Tool Calling、Workflow 与业务 Harness 快速接入实际流程。

这种方式能够快速完成业务闭环，但实际运行中仍然存在：

- 长链路任务容易步骤遗漏或提前终止；
- 模型可能选择错误工具；
- 工具参数生成可能不符合实际约束；
- 环境状态变化后，模型可能沿用旧计划；
- 工具失败后的恢复能力不稳定；
- 仅依赖 Prompt、Workflow 或 Harness 很难直接提升模型自身的工具使用能力。

因此，本项目进一步研究：

> 能否通过数据构造、SFT、偏好优化与强化学习，提高 Tool-Use Agent 在长链路软件任务中的可靠性、任务完成率和异常恢复能力？

## 模型优化路线

计划依次比较：

1. Base Instruction Model
2. LoRA SFT
3. DPO
4. GRPO（资源和时间允许时）

## 核心评测指标

- 工具选择准确率
- 参数生成准确率
- 合法工具调用率
- 长链路任务成功率
- 异常恢复成功率
- 幻觉工具调用率
- 平均执行步骤
- Token 消耗
- 端到端延迟

## 数据飞轮

通过 held-out benchmark 收集模型 Bad Case，包括：

- 工具选择错误
- 参数错误
- 调用格式错误
- 执行顺序错误
- 状态理解错误
- 异常后无法恢复
- 任务提前结束

针对这些失败类型构造新的训练轨迹，形成：

模型评测 -> Bad Case 分析 -> 数据构造 -> 再训练 -> 再评测

的数据迭代闭环。

## 隐私边界

本仓库中的数据、工具、环境和业务规则均为独立设计与合成生成。

项目仅抽象真实业务 Agent 中观察到的通用工程问题，不包含任何前雇主的内部代码、数据、接口、文档或实现细节。
