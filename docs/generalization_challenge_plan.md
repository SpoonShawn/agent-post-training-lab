# 泛化挑战：构造前方案草案（尚未冻结/运行）

## 研究问题

固定pilot_v1最后adapter，测试收益能否越过当前配置事务模板；不以继续降低验证loss为目标，不据已看过的确认集调参。本轮定位为训练后诊断，不追溯宣称它是训练前预注册测试。

## 拟测维度

1. 表达稳健性：相同任务语义，不同叙述顺序和自然语言；与原表达成对比较，单报改写前后差值。这部分属于既有任务的压力测试，不称全新独立场景。
2. 动作结构：设置次数改为1、2、4、5次及重复档位，终止页面变化；以完整动作结构分组，不能只按句子随机拆分。oracle需证明顺序检查不会把重复动作漏掉。
3. 约束遵循：只读、不导航、不修改画质等与相应任务相容的明确约束；不得在题面没写时暗设禁令，也不得要求互相矛盾的目标。
4. 故障目标变化：在导航、返回首页或启动副本等已支持操作的首次合法调用注入故障；题面公开失败后的处理要求。现模拟器不支持第N次命中才开始失败，本轮不默默加入该机制。

## 比较与报告约定

- Base与现有SFT使用相同基础权重、工具、输入、greedy及token/步骤预算；分别报告每个维度、每组结果，不只报总分。
- 主指标执行成功；次指标为带来源和审阅类型的答案复核结果；失败次数一致性只是辅助审计。
- 先验证每题oracle通过，再用缺日志、错顺序、无视约束、跳过恢复检查等反例验证拒绝能力。若发现协议缺陷，版本化并说明影响，不能偷偷修好后覆盖旧分数。
- 正式数据规模/组数及预算在生成检查后、首次模型运行前写入冻结manifest；此草案不冒充已冻结协议。
- 不以80个表述变体当80个独立样本；不据单次训练/少数组声称显著或稳定。优先展示按组失败情况及真实bad case。
- 新集不用于当前adapter继续训练。若据其结果开发下一版，它随即成为开发诊断数据，需要新确认集。

## 面试可讲与不可讲

已具备证据：合成状态机、可控故障、分层评估、评估版本审计、按组合隔离数据、assistant-only LoRA、H800真实训练、Base/SFT配对结果、来源指纹、工具重放，以及失败后错误总结的案例。

暂缺证据：复杂真实业务效果、强域外泛化、独立盲审、多随机种子稳定性、与更简单方法的充分对照。后续可增加相同工具提示下的明确规划清单基线，单独标为prompt干预；不要只和较弱默认提示比就断言训练是唯一解决办法。

目前适合描述为“小规模可复现的Agent后训练与评估实验”。用户应能解释数据如何产生、分组为何能减少泄漏、标签掩码如何计算、失败次数从哪里取、为什么不能把100%外推；同时如实说明使用AI辅助开发与审计，不虚构个人独立完成的工作。
